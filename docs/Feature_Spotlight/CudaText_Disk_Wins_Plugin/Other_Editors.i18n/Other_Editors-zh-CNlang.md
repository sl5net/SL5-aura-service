# 在其他编辑器中自动重新加载

本文档介绍了如何设置外部自动重载
常见编辑器中的文件更改 - 以及为什么这通常**不够**
在 Aura Oma 模式下。

---

## 凯特（KDE）

＃＃＃ 设置

1. **设置 → 配置 Kate → 打开/保存 → 高级**
2. 启用：
- **“自动重新加载文件”**

### 什么有效

- 当缓冲区**未更改**时，Kate 立即重新加载文件。
- 这对于纯观看模式来说已经足够了。

### 什么**不起作用**（以及为什么它在 Oma 模式下失败）

- 一旦您按下缓冲区中的**单个键**（即使只是一个
空格或意外击键），缓冲区被视为“已修改”。
- 从那一刻起，凯特**总是**询问每一个外部变化：
>“文件已从外部更改。您要重新加载吗？”
- 在 Oma 模式下，用户可能不在计算机旁或看不到
对话框 - Aura 继续写作，但编辑器仍保留旧版本。
- **Kate 没有设置** 静默丢弃未保存的缓冲区更改
支持磁盘版本。

> **底线：** Kate 一旦用户就不适合 Oma 模式
> 不小心在编辑器中输入了内容。

### 限制

- `autoSave` 保存缓冲区 — 它会覆盖 Aura 的更改
本地版本，而不是相反。
- 对于未保存的更改，仍会出现提示。
- 没有“磁盘总是获胜”的选项。

模态或无模态。

## 为什么没有编辑器可以开箱即用地做到这一点

默默地丢弃未保存的更改被认为是**大量数据丢失
软件开发中的错误**。没有严肃的编辑器提供设置
“不询问就覆盖我的缓冲区”。这是正确且重要的——
用于正常的开发人员工作。

然而，在 Aura Oma 模式中，优先级相反：Aura 是源头
事实是，人类编辑器缓冲区是次要的。因此一个
需要显式插件干预来强制执行此行为
这个特定的用例。
