# 동기 부여: 왜 "디스크가 승리"합니까?

## 아우라 할머니모드의 문제점

[Aura Oma Mode](../../../GettingStarted.i18n/GettingStarted-kolang.md)(67행 참조)에서 Aura는 대체로 자율적으로 작동합니다.
사용자는 명령을 말하고 Aura는 스스로 파일에 씁니다.
구성, 스크립트, 로그 항목, 생성된 텍스트.

다음 시나리오는 지속적으로 발생합니다.

1. 사용자의 편집기에 파일이 열려 있습니다(예: 규칙 파일 또는 스크립트).
2. 그들은 편집기가 아직 활성화되어 있다는 사실을 잊어버리고 Aura 명령을 말합니다.
3. Aura는 디스크의 파일을 변경합니다.
4. 편집자는 외부 변화를 감지하고 **질문**합니다.

이 프롬프트는 Oma 모드의 **쇼스토퍼**입니다.
- 사용자는 소파에 앉아 음성 입력을 사용할 수 있으며,
대화 상자를 보거나 연결할 수 없습니다.
- 또는 실수로 편집기에서 키를 눌렀을 때 버퍼가 이제
"수정"되고 모든 외부 변경 사항은 다음과 같이 차단됩니다.
"새로고침하시겠습니까? / 로컬을 유지하시겠습니까?" 대화.
- 결과: Aura는 계속 작동하지만 편집기에는 오래된 버전이 표시됩니다.
사용자는 현재 파일을 보고 있다고 생각하지만 편집 내용은
오래된 상태에서는 혼돈이 보장됩니다.

## 우리에게 필요한 것

**항상 디스크 우선순위**를 지정하는 편집기 동작입니다.
Aura(또는 다른 도구)가 파일을 변경할 때 편집자는 다음을 수행해야 합니다.
즉시 **메시지 없이** 새 콘텐츠를 표시합니다.
편집기에 저장되지 않은 입력은 자동으로 삭제될 수 있습니다.
Oma 모드, Aura는 인간의 키보드 입력이 아닌 진실의 원천입니다.

## 표준 편집기가 실패하는 이유

거의 모든 일반 편집기(Kate, VS Code, Sublime Text, Notepad++,
Emacs, Vim, CudaText 기본 제공)에는 다음과 같은 보호 메커니즘이 있습니다.
버퍼에 저장되지 않은 변경 사항이 포함되면 **항상** 묻습니다.
외부 변화가 일어날 때. 이는 일반용의 기능입니다.
개발자 작업이지만 Aura Oma 모드의 버그입니다.

이 플러그인은 CudaText의 격차를 정확히 줄여줍니다.

## 대상 고객

- 편집기에서 파일을 병렬로 보는 Aura Oma 모드 사용자입니다.
- 프로세스가 파일과 편집기를 작성하는 자동화 시나리오
라이브 뷰어 역할만 수행합니다.
- "디스크가 항상 승리"하는 사람은 누구나 바람직한 행동입니다.
