# 他のエディタでの自動リロード

このドキュメントでは、外部デバイスで自動リロードを設定する方法について説明します。
一般的なエディタでのファイル変更 — そしてこれがしばしば**十分ではない**理由
オーラオーマモードで。

---

## ケイト (KDE)

＃＃＃ 設定

1. **設定 → Kate の設定 → 開く/保存 → 詳細設定**
2. 以下を有効にします。
- **「ファイルを自動的に再ロードする」**

### 何が機能するのか

- バッファーが **変更されていない**場合、Kate はファイルをすぐに再ロードします。
- 純粋な表示モードにはこれで十分です。

### 何が**機能しない** (そして、Oma モードで失敗する理由)

- バッファー内の **単一のキー**を押すとすぐに (キーだけでも)
スペースまたは偶発的なキーストロークなど）、バッファは「変更された」とみなされます。
- その瞬間から、ケイトは**常に**、外部の変化について次のように尋ねます。
> 「ファイルは外部で変更されました。再読み込みしますか?」
- Oma モードでは、ユーザーはコンピュータの前にいない場合や、
ダイアログ — Aura は書き込みを続けますが、エディターは古いバージョンのままです。
- **Kate には、保存されていないバッファの変更をサイレントに破棄する設定がありません**
ディスク版を支持します。

> **結論:** ケイトはユーザーがすぐにオマモードに適さない
> 誤ってエディタに入力してしまいました。

## VS コード

＃＃＃ 設定

「settings.json」内:

```json
{
    "files.autoSave": "afterDelay",
    "files.autoSaveDelay": 1000
}
```

### 制限事項

- `autoSave` はバッファを保存します。Aura の変更を上書きします。
ローカルバージョンです。その逆はありません。
- 変更が保存されていない場合は、プロンプトが表示されます。
- 「ディスクが常に優先」のオプションはありません。

---

## Emacs

```elisp
(global-auto-revert-mode t)
```

### 制限事項

- バッファが変更されていない場合にのみ自動的にリロードされます。
- バッファがいつ変更されたかを尋ねます。

---

## ヴィム / ネオヴィム

```vim
set autoread
au FocusGained,BufEnter,CursorHold * :checktime
```

### 制限事項

- `autoread` はバッファが変更されていない場合にのみリロードします。
- 「変更された」バッファを自動的に上書きしません。

---

## CudaText (プラグインなし)

「user.json」内:

```json
{
    "ui_notif": true,
    "ui_notif_confirm": 0
}
```

### 制限事項

- `ui_notif_confirm` のすべての値 (0 ～ 4) は、何らかの形式のプロンプトを表示します。
モーダルまたはモーダルレス。
- 「すぐにリロードし、尋ねない」を意味する **no** 値があります。
- したがって、「cuda_disk_wins」プラグインが必要です。

---

＃＃ 概要

|編集者 |自動リロード (変更なし) |自動リロード (修正) |ライセンス |
|----------|----------------------|--------------------------|-----------|
|ケイト |はい |常にプロンプトを表示する |オープンソース |
| VSコード |はい |常にプロンプトを表示する |オープンソース |
|崇高なテキスト |はい |常にプロンプトを表示する |独自の |
| Emacs |はい |常にプロンプトを表示する |オープンソース |
|ヴィム |はい |常にプロンプトを表示する |オープンソース |
| CudaText (プラグインなし) |はい |常にプロンプトを表示する |オープンソース |
| **CudaText + ディスクの勝利** |はい | **プロンプトなし** |オープンソース |

## なぜこれをすぐに実行できるエディタがないのか

保存されていない変更をサイレントに破棄すると、**大規模なデータ損失とみなされます
ソフトウェア開発におけるバグ**。まともな編集者は設定を提供していない
「質問せずにバッファを上書きします」。これは正しくて重要です —
通常の開発者の作業用。

ただし、Aura Oma モードでは優先順位が逆になり、Aura がソースになります。
人間の編集者のバッファは二次的なものです。したがって、
この動作を強制するには、プラグインの明示的な介入が必要です。
この特定の使用例。
